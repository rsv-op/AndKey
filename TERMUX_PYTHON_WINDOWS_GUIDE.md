# BuildGenie — Termux · Python · Windows Shell Operating Guide

> Exact, copy-paste steps for the three environments used to operate the **BuildGenie Offline APK**
> (`com.buildgenie`) on your Android phone, covering the four required functions:
>
> | # | Required function | What it means for this APK |
> |---|-------------------|----------------------------|
> | 1 | **Load files** | Stage data files into the app (SAF Inbox, seed button, or push via adb/Termux) |
> | 2 | **Inspect files** (`.gguf` / `.litert` / `.ablitert`) | Parse model headers: magic, version, tensors, metadata — without executing them |
> | 3 | **Generate files** | Create reports/manifests/stub models with Python; create build-guide PDFs in-app |
> | 4 | **Replace files** | Atomically swap a model or data file with automatic `.bak` backup + restore |
>
> Every command below is written to be run verbatim. Each step includes a **Verify** line so you
> (or an AI agent) can confirm success before moving on. Tool used throughout: `tools/model_toolkit.py`
> (Python 3.8+, standard library only, zero network calls — matches the APK's zero-network policy).

## 0. Prerequisites (download once)

| Item | Where | Notes |
|------|-------|-------|
| BuildGenie APK | [Releases → Latest](https://github.com/rsv-op/AndKey/releases/latest) → `app-debug.apk` or `app-release.apk` | Also in **Actions → BuildGenie Offline APK & Model Bundler → Artifacts → BuildGenie-Offline-APK** |
| Termux | [F-Droid: com.termux](https://f-droid.org/packages/com.termux/) | Install from F-Droid or the [Termux GitHub releases](https://github.com/termux/termux-app/releases) — **not** Play Store (outdated) |
| Python 3.8+ | Termux: `pkg install python` · Windows: `winget install Python.Python.3.12` | `model_toolkit.py` uses stdlib only — no `pip install` needed |
| ADB (Windows only) | `winget install --id Google.PlatformTools` or [platform-tools zip](https://dl.google.com/android/repository/platform-tools-latest-windows.zip) | Needed to install/push/pull from a PC |

**Phone-side layout used by this guide (create it once):**

```text
/sdcard/Download/BuildGenie/
├── models/          ← side-loaded .gguf / .litert / .ablitert models
├── inbox/           ← SAF Inbox folder you pick inside the app
└── (PDFs generated by the app land here automatically)
```

## 1. Termux (on the Android phone)

### 1.1 One-time setup

```bash
pkg update -y && pkg upgrade -y
pkg install -y python git curl
termux-setup-storage          # tap ALLOW when Android asks for file access
mkdir -p /sdcard/Download/BuildGenie/{models,inbox}
```

**Verify:**

```bash
python --version              # expect: Python 3.11.x (or newer)
ls /sdcard/Download/BuildGenie   # expect: inbox  models
```

> If `ls /sdcard` says *Permission denied*: open **Settings → Apps → Termux → Permissions →
> Files and media → Allow**, then run `termux-setup-storage` again. On some Android 13+ devices
> you must grant **All files access** (Settings → Apps → Special access → All files access).

### 1.2 Get the toolkit onto the phone

Option A — git clone (recommended):

```bash
cd ~
git clone --depth 1 https://github.com/rsv-op/AndKey.git
cd AndKey
```

Option B — single-file download:

```bash
curl -L -o ~/model_toolkit.py \
  https://raw.githubusercontent.com/rsv-op/AndKey/main/tools/model_toolkit.py
cd ~
```

**Verify (either option):**

```bash
python model_toolkit.py --version || python AndKey/tools/model_toolkit.py --version
# expect: model_toolkit 1.0.0
```

> From here on, commands assume you are in the directory containing `model_toolkit.py`.
> If you used Option A: `cd ~/AndKey && cd tools` (or prefix commands with `python tools/model_toolkit.py`).

### 1.3 Install the APK from Termux

```bash
curl -L -o /sdcard/Download/BuildGenie.apk \
  https://github.com/rsv-op/AndKey/releases/latest/download/app-debug.apk
termux-open /sdcard/Download/BuildGenie.apk    # Android package installer opens
```

- If prompted, allow Termux to **install unknown apps** (Settings → Apps → Termux → Install unknown apps).
- Tap **Install** in the system dialog.

**Verify:**

```bash
pm list packages | grep buildgenie     # expect: package:com.buildgenie
```

> Without a PC you can also download the APK in any browser from the Releases page and tap the
> file in your file manager to install.

### 1.4 The four required functions in Termux

#### ① Load files

```bash
# Copy any data/model file into the app's shared world:
cp ~/support_tickets.csv /sdcard/Download/BuildGenie/inbox/
cp ~/my-model.gguf       /sdcard/Download/BuildGenie/models/

# Then in the app: open BuildGenie → tap "1. Pick SAF Inbox" → select
# /sdcard/Download/BuildGenie/inbox  → files appear under "Staged Files".
# Or tap "2. Seed Sample Files" to load the built-in demo CSV/JSONL/YAML.
```

**Verify:**

```bash
ls -lh /sdcard/Download/BuildGenie/inbox/
python model_toolkit.py load /sdcard/Download/BuildGenie/models/my-model.gguf
# expect: LOAD OK ... sha256: <hex> ... format: gguf
```

#### ② Inspect files (`.gguf` / `.litert` / `.ablitert`)

```bash
python model_toolkit.py inspect /sdcard/Download/BuildGenie/models/my-model.gguf
python model_toolkit.py inspect /sdcard/Download/BuildGenie/models/encoder.litert
python model_toolkit.py inspect /sdcard/Download/BuildGenie/models/legacy.ablitert
```

Expected output (GGUF):

```text
INSPECT OK
  format   : gguf
  --- GGUF header ---
  version  : 3
  tensors  : <n>
  metadata : <n> KV pair(s)
    general.architecture = llama
    ...
```

Expected output (LiteRT family — detected by magic bytes, not extension):

```text
INSPECT OK
  format   : litert
  --- LiteRT / TFLite FlatBuffer ---
  identifier  : TFL3
  model ver   : 3
  subgraphs   : <n>
```

Add `--json` for machine-readable output (for AI agents / scripts).

#### ③ Generate files

```bash
# JSON inspection report for one model:
python model_toolkit.py generate report /sdcard/Download/BuildGenie/models/my-model.gguf \
  -o /sdcard/Download/BuildGenie/my-model.report.json

# Inventory of every file in a folder (name, size, sha256, format):
python model_toolkit.py generate manifest /sdcard/Download/BuildGenie/models \
  -o /sdcard/Download/BuildGenie/models.manifest.json

# A minimal, valid GGUF stub (for pipeline testing):
python model_toolkit.py generate stub-gguf /sdcard/Download/BuildGenie/models/stub.gguf \
  --name my-stub --arch llama
```

In-app generation: tap any **build suggestion** button in BuildGenie → a zero-metadata PDF is
written to `/sdcard/Download/BuildGenie/` (MediaStore path `Download/BuildGenie/`).

**Verify:**

```bash
ls -lh /sdcard/Download/BuildGenie/*.json /sdcard/Download/BuildGenie/*.pdf 2>/dev/null
```

#### ④ Replace files

```bash
# Safe swap: backs up the old file to <name>.bak-<timestamp>, then overwrites,
# then re-hashes both sides and refuses to finish on mismatch:
python model_toolkit.py replace \
  /sdcard/Download/BuildGenie/models/my-model.gguf \
  /sdcard/Download/BuildGenie/models/my-model-v2.gguf
# expect: REPLACE OK ... backup: ...bak-YYYYMMDD-HHMMSS ... verified: hashes match

# Undo it:
python model_toolkit.py replace --restore /sdcard/Download/BuildGenie/models/my-model.gguf
# expect: RESTORE OK
```

Guarantees: refuses **format mismatches** (e.g. pushing a `.litert` over a `.gguf`) unless you
pass `--force`; refuses to clobber files that fail parsing (unless `--force`); replacement is
atomic (`write temp → fsync → rename`), so a crash can never leave a half-written model.

After replacing a model, **restart BuildGenie** so `LocalAiChatEngine` re-checks
`files/models/local_llm_q4.onnx` and `/sdcard/Download/BuildGenie/models/`.

## 2. Python (same CLI on Termux *and* Windows)

`model_toolkit.py` is one file, stdlib-only, offline. The four functions map to subcommands:

```text
python model_toolkit.py load      PATH                       → function ①
python model_toolkit.py inspect   PATH [--json] [--max-kvs N] → function ②
python model_toolkit.py generate  report|manifest|stub-gguf   → function ③
python model_toolkit.py replace   TARGET SOURCE [--restore]   → function ④
```

### ① load — validate identity of a file

```bash
python model_toolkit.py load ./my-model.gguf
```

```text
LOAD OK
  path    : /home/you/my-model.gguf
  size    : 149 bytes (149 bytes)
  sha256  : c647c40e...
  format  : gguf
```

Exit codes: `0` found · `1` file not found · `2` unreadable · `3` bad usage.

### ② inspect — parse `.gguf` / `.litert` / `.ablitert`

```bash
python model_toolkit.py inspect ./my-model.gguf          # human-readable
python model_toolkit.py inspect ./encoder.litert --json  # for scripts/AI
python model_toolkit.py inspect ./big.gguf --max-kvs 100 # sample more metadata
```

- **GGUF**: magic `GGUF`, version, tensor count, metadata KV count, first KV pairs
  (`general.architecture`, `general.name`, quantization, …).
- **LiteRT family** (`.litert`, `.ablitert`, `.tflite`): FlatBuffer root offset, file identifier
  (`TFL3`), model version, description, subgraph/operator-code/buffer counts.
- **Detection is by content, not extension** — a file named `.ablitert` that really contains GGUF
  data is reported as `gguf`.
- Unknown formats are still reported: size, sha256, first 16 bytes hex.

### ③ generate — create files

```bash
python model_toolkit.py generate report ./my-model.gguf -o ./report.json
python model_toolkit.py generate manifest ./models_dir -o ./manifest.json
python model_toolkit.py generate stub-gguf ./stub.gguf --name demo --arch llama
```

| Generator | Output | Use |
|-----------|--------|-----|
| `report` | JSON: full inspect result + timestamp | Attach inspection evidence to a release/PR |
| `manifest` | JSON: every file in a directory with size/sha256/format | Inventory before/after a replace |
| `stub-gguf` | Minimal valid GGUF (v3, 3 metadata KVs, self-verified) | Test the inspect/replace pipeline without a 400 MB download |

### ④ replace — atomic swap with backup

```bash
python model_toolkit.py replace ./model.gguf ./model-v2.gguf
python model_toolkit.py replace ./model.gguf ./model-v2.gguf --no-backup
python model_toolkit.py replace ./model.gguf ./model-v2.gguf --force   # skip guards
python model_toolkit.py replace --restore ./model.gguf                 # undo
```

Sequence performed: validate source parses → copy target to `target.bak-<ts>` → write source to a
temp file in the same directory → `fsync` → `os.replace` → re-hash and compare → print `REPLACE OK`.

**Programmatic use (import it):**

```python
import model_toolkit as mt
mt.cmd_load(...)       # or call mt.inspect_gguf(path), mt.inspect_litert(path) directly
```

## 3. Windows Shell (PowerShell or CMD, via adb)

### 3.1 One-time setup

```powershell
# PowerShell — install Python and adb:
winget install Python.Python.3.12
winget install --id Google.PlatformTools -e
# (If winget ID is unavailable, download https://dl.google.com/android/repository/platform-tools-latest-windows.zip,
#  extract to C:\platform-tools, then:  $env:Path += ";C:\platform-tools" )
```

Close and reopen the terminal, then:

```powershell
python --version     # expect: Python 3.12.x
adb version          # expect: Android Debug Bridge version 1.0.41...
```

On the phone: **Settings → About phone → tap "Build number" 7× → Settings → System →
Developer options → USB debugging → ON**. Connect the phone via USB, choose **File Transfer (MTP)**
if the cable prompts, then:

```powershell
adb devices
# expect a line like:  <serial>    device
# If it says "unauthorized": unlock the phone and tap ALLOW USB debugging (check "Always allow").
```

Get the APK and toolkit on the PC:

```powershell
# Clone the repo (contains tools\model_toolkit.py + gradlew.bat):
git clone https://github.com/rsv-op/AndKey.git
cd AndKey

# Or just fetch the APK directly:
Invoke-WebRequest -Uri https://github.com/rsv-op/AndKey/releases/latest/download/app-debug.apk `
                  -OutFile app-debug.apk
```

Install the APK:

```powershell
adb install -r .\app-debug.apk        # -r = reinstall/upgrade, keeps app data
# expect: Success
```

**Verify zero-network guarantee:**

```powershell
adb shell dumpsys package com.buildgenie | Select-String "INTERNET"
# expect: NO matches (the INTERNET permission is stripped via tools:node="remove")
```

CMD equivalent: `adb shell dumpsys package com.buildgenie | findstr INTERNET`

### 3.2 The four required functions from Windows Shell

#### ① Load files

```powershell
# Create the folder structure on the phone:
adb shell mkdir -p /sdcard/Download/BuildGenie/models
adb shell mkdir -p /sdcard/Download/BuildGenie/inbox

# Push files from the PC:
adb push .\support_tickets.csv /sdcard/Download/BuildGenie/inbox/
adb push .\my-model.gguf       /sdcard/Download/BuildGenie/models/

# Optional: write directly into the app's private staging dir (DEBUG APK only —
# release builds block run-as). After this, the app's FileObserver fires automatically:
adb push .\support_tickets.csv /data/local/tmp/support_tickets.csv
adb shell run-as com.buildgenie sh -c "mkdir -p files/staging && cp /data/local/tmp/support_tickets.csv files/staging/"
```

Then on the phone: open BuildGenie → **"1. Pick SAF Inbox"** → select
`/sdcard/Download/BuildGenie/inbox` → staged files render in the list.

**Verify:**

```powershell
adb shell ls -l /sdcard/Download/BuildGenie/inbox/
python .\tools\model_toolkit.py load .\my-model.gguf
```

#### ② Inspect files (`.gguf` / `.litert` / `.ablitert`)

Inspect on the PC before pushing (recommended for multi-GB models):

```powershell
python .\tools\model_toolkit.py inspect .\my-model.gguf
python .\tools\model_toolkit.py inspect .\encoder.litert --json
python .\tools\model_toolkit.py inspect .\legacy.ablitert
```

Or pull a model that is already on the phone, inspect, and push back:

```powershell
adb pull /sdcard/Download/BuildGenie/models/my-model.gguf .\pulled-model.gguf
python .\tools\model_toolkit.py inspect .\pulled-model.gguf
```

**Verify:** exit code `$LASTEXITCODE -eq 0` and the `INSPECT OK` banner (see §2 for expected output).

#### ③ Generate files

```powershell
# Inspection report + directory manifest on the PC:
python .\tools\model_toolkit.py generate report .\my-model.gguf -o .\my-model.report.json
python .\tools\model_toolkit.py generate manifest .\models -o .\models.manifest.json

# Test stub:
python .\tools\model_toolkit.py generate stub-gguf .\stub.gguf --name win-stub --arch llama

# Pull the zero-metadata PDF the app generated on the phone:
adb pull /sdcard/Download/BuildGenie/ .\BuildGenie-output\
```

#### ④ Replace files

```powershell
# Pull → back up on the PC → replace on the PC → push back:
adb pull /sdcard/Download/BuildGenie/models/my-model.gguf .\my-model.gguf
adb pull /sdcard/Download/BuildGenie/models/my-model-v2.gguf .\my-model-v2.gguf
python .\tools\model_toolkit.py replace .\my-model.gguf .\my-model-v2.gguf
# expect: REPLACE OK ... verified: hashes match

# Push the swapped file back (adb push is itself atomic enough for a staged file;
# the toolkit already created .\my-model.gguf.bak-* as your rollback point):
adb push .\my-model.gguf /sdcard/Download/BuildGenie/models/my-model.gguf

# Undo entirely:
python .\tools\model_toolkit.py replace --restore .\my-model.gguf
adb push .\my-model.gguf /sdcard/Download/BuildGenie/models/my-model.gguf
```

Restart BuildGenie on the phone after a model swap.

### 3.3 PowerShell-only conveniences

```powershell
# Script the whole verify loop:
$apk = ".\app-debug.apk"
adb install -r $apk
if ($LASTEXITCODE -ne 0) { throw "install failed" }
adb shell pm list packages | Select-String buildgenie        # package:com.buildgenie
python .\tools\model_toolkit.py inspect .\my-model.gguf --json | ConvertFrom-Json | Select-Object format, tensor_count
Write-Host "All checks passed"
```

## 4. End-to-end recipes (pick your environment)

**Recipe A — first install + load + inspect (no PC needed):**
1. Termux: follow §1.1 → §1.3 (install APK) → §1.4① (load files) → §1.4② (inspect model).
2. In the app: *"1. Pick SAF Inbox"* → `/sdcard/Download/BuildGenie/inbox` → *"2. Seed Sample Files"*.

**Recipe B — model upgrade with rollback:**
1. Windows: `adb push` new model to `/sdcard/Download/BuildGenie/models/` (§3.2①).
2. Anywhere: `python model_toolkit.py inspect` the new file (must print `INSPECT OK`).
3. `python model_toolkit.py replace <old> <new>` → note the `.bak-` path printed.
4. Restart BuildGenie → chat shows `[Local ONNX Int4 Runtime Active]` (side-loaded weights found).
5. If anything is wrong: `python model_toolkit.py replace --restore <old>` → restart app.

**Recipe C — evidence bundle for a release/PR:**
```bash
python model_toolkit.py generate report  ./my-model.gguf -o ./report.json
python model_toolkit.py generate manifest ./models_dir  -o ./manifest.json
python model_toolkit.py inspect ./my-model.gguf --json >> ./report.json
```

## 5. Troubleshooting

| Symptom | Fix |
|---------|-----|
| Termux: `Permission denied` on `/sdcard` | Settings → Apps → Termux → Permissions → Files and media → **Allow**; re-run `termux-setup-storage` |
| Termux: `pkg` 404/rotation errors | `termux-change-repo` → pick a mirror → `pkg update` |
| `adb devices` empty | Change USB mode to **File Transfer**; try another cable/port; reinstall OEM USB driver |
| `adb devices` = `unauthorized` | Unlock phone → accept **Allow USB debugging** dialog |
| `adb install` = `INSTALL_FAILED_ALREADY_EXISTS` | Use `adb install -r` or first `adb uninstall com.buildgenie` |
| `python` not found on Windows | Use `py -3` launcher, or reopen the terminal after `winget install` |
| `replace` exits 2: *format mismatch* | Expected guard — inspect both files; add `--force` only if intentional |
| `replace` exits 2: *source parse failed* | The source file is corrupt/truncated; re-download it |
| App doesn't see a pushed model | Restart the app (model check runs at chat startup); confirm path `/sdcard/Download/BuildGenie/models/` |
| `run-as com.buildgenie` fails | Only **debug** APKs are debuggable; use the SAF Inbox path instead |
| GGUF inspect shows `parse_error` | File truncated mid-download — compare `sha256` from `load` against the source |

**Exit-code contract (for AI agents):** `0` = success · `1` = file/dir not found ·
`2` = parse or validation failure · `3` = wrong usage. All commands also accept `--json` where
output is structured (`load`, `inspect`, `generate report|manifest`, `replace`).
